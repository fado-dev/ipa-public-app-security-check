## 不審な User-Agent

`scripts/scan_logs.sh` はこのセクションの文字列を部分一致で照合する。

```ioc-ua
curl/7.88.1
python-requests/2.34.2
python-requests/2.33.1
Metabase-GHSA-vwf4/2.0
```

一般的な Chrome の User-Agent を偽装したアクセスも報告されている。UA だけでは判別できないため、
同一 IP からの短時間大量アクセス、画面遷移を伴わない API 直叩き、認証失敗の連続などと組み合わせて見る。

## 手口別の痕跡

### ケースA: 既知脆弱性の探索・設定不備の悪用
- 複数の既知脆弱性に対応するパス・ペイロードを短時間に順番に試行（スキャナ的な挙動）
- 環境設定ファイル・バックアップファイルへのアクセス試行: `.env`, `.git/`, `config.*`, `*.bak`, `*.sql`, `*.zip`, `*.tar.gz`, `backup*`, `dump*`, `phpinfo`, `.DS_Store`
- 4xx が大量に出た直後に 200 が返っているパス（探索が成功した可能性）

### ケースB: 管理用 API の不正操作
- 公開モバイルアプリの解析で特定された API エンドポイント・キーの利用
- 画面操作では呼ばれない内部 API・管理 API への直接アクセス
- 認証ヘッダーの有無・不正形式トークンでの応答差の探索（401/403/400 のパターン）
- NoSQL インジェクションのブラインド探索（`$ne`, `$gt`, `$regex`, `$where` などを含むクエリ・ボディ、応答時間差）
- ユーザー権限の変更、不正アカウントの作成（操作ログで確認）
- 他システムから窃取した API キーの利用（発行元と利用元の不一致）

### ケースC: Metabase SQL インジェクション (CVE-2026-72898)
- Metabase の API への不正リクエスト（詳細は JPCERT at260023 を参照）
- UA `Metabase-GHSA-vwf4/2.0`
- Metabase のクエリ実行ログに通常の BI 利用と異なる SQL（`UNION`, `information_schema`, システムテーブル参照、大量行の取得）

### ケースD: Web シェルの設置
- 公開 Web サーバからアクセス可能な AP サーバ上の `.war` ファイル配置（Tomcat 等の自動デプロイ先 `webapps/` など）
- WAR 内の JSP が簡易 Web シェルとして動作し、特定のクエリパラメータの値をシェルコマンドとして実行
- アクセスログに見覚えのない `.jsp` へのリクエスト、`cmd=`, `exec=`, `command=` などのパラメータ
- `scripts/find_webshell.sh` で最近作成・変更されたファイルを列挙して確認

## 汎用的な異常指標（JPCERT の手口から導いた例）

- API: 短時間に大量のリクエストがある IP、本来画面から呼ばれないエンドポイントへのアクセス、権限変更・新規アカウント作成の操作履歴
- 認証: ログイン、パスワードリセット、SMS 送信の異常な回数、ログイン元 IP・時間帯の平時との差
- Web/AP サーバ: 不審な `.war`・`.jsp` の作成・変更、同一パラメータを含む GET/POST の繰り返し、設定ファイル・バックアップへのアクセス
- BI ツール: 通常業務と異なるクエリ実行
